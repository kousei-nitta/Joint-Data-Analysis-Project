# 試作品の方針（アプリ実装前）

## 今回準備した基盤

- Python 3.12.11を使用。pyenvはPython選択、uvはプロジェクトの`.venv`と依存関係を担当する。
- pandas＋openpyxlでxlsxを読む。既存のExcelを入力元にし、アプリから書き戻さない。
- Streamlitでローカルブラウザ画面、Plotlyで拡大・値の確認ができるグラフを作る。
- `uv.lock`で間接依存まで固定。CIでも同じPython・uv・依存関係を使う。
- サーバーは127.0.0.1で待ち受ける。公開・認証・データベース・Dockerは今回の範囲外。

Streamlitなら画面用のJavaScriptを別に用意せずPython中心で試作できる。
独立したAPIや複雑な画面が必要になれば、次の段階で構成を再検討する。

## 入力するExcel

既存ファイルはリポジトリ直下の `product_prices.xlsx`。1行目が見出し。
テンプレートには空行があるため、読み込み後に完全な空行だけを除外する。

| シート | 列 | 読み取り方針 |
| --- | --- | --- |
| 価格履歴 | 確認日・商品ID・価格・備考 | 1行が1回の価格記録。備考は任意 |
| 商品マスタ | 商品ID・商品名 | 商品IDを一意に管理 |

- 商品IDは文字列として読み、先頭ゼロを保持する。Excel側でも文字列で入力する。
- 確認日は日付、価格は数値として検証する。空欄を0円扱いしない。
- 入力規則は貼り付けなどで回避され得るため、Python側でも不正値・未登録IDを検証する。
- 商品マスタのID重複や必須項目の欠落は、該当行を示して修正を促す。
- マスタ結合で未登録IDを黙って捨てない。日付順に並べてグラフを表示する。
- 今回の環境確認はメモリ内のサンプルを使用し、実際の商品データをCIに出力しない。

## 最初のアプリ案（まだ未実装）

1. ブラウザでxlsxを1ファイル選ぶ（上限20MB）。
2. シート・列・値を検証し、問題があれば理由と行を表示する。
3. 商品を選ぶ。期間を絞り、価格の折れ線グラフと元の表を表示する。
4. 必要ならグラフをHTMLとしてダウンロードする。

業務処理と画面処理を分け、読み込み・検証・グラフ生成を個別にテストできる構成にする。
詳細なファイル分割は最初の実装時に決める。

## 実装前に確認すること

- 価格は税込か税抜か、通貨は円のみか、数量・容量の単位は一定か。
- 同じ商品・同じ日に複数の価格がある場合、店舗・時間などで区別する必要があるか。
- 0円の扱い、負の価格の禁止、必須項目の範囲。
- 商品名が未登録の行をエラーにするか、IDだけで表示を許可するか。
- グラフは最初から複数商品を比較するか、まず1商品ずつにするか。

重複を勝手に平均したり、欠損価格を補完したりしない。
最初の実装PRの完了条件は、正常な入力のグラフ表示と、誤った入力への明確な案内を確認して決める。
