# 反復開発（Loop Engineering）と人間の承認ゲート

## 原則
AIは**個々の作業セッション内で**「計画→実装→自動テスト→原因分析→改善→再テスト」を必要な回数実施する。ただし、無人で将来にわたり走り続ける仕組みはこのリポジトリには存在しない。各モデルを変えても、事実・検証結果・次のタスクはGitHubのPRと本ディレクトリのドキュメントに残す。

## PDCAの単位
| 段階 | 担当AIの具体的動作 | 証拠 |
| --- | --- | --- |
| Plan | 入力仕様、対象ファイル、期待される出力、失敗時の扱いを確定 | PR本文・仕様書 |
| Do | 専用ブランチで最小単位の変更。原本Excelに書き込まない | コミットdiff |
| Check | `ruff check`、`ruff format --check`、`pytest`、デモHTML生成を実行 | 実行結果/CI |
| Act | 失敗原因を特定し、修正し、同じ検証を再実行。推測は未検証と区別 | 追記コミット/PR説明 |

## 現行の承認ゲート（mainへの反映は人間が決める）
- **Gate 1：設計確認** — 非公開Googleシート・JPY・既存2タブ・APIの無料枠と課金リスクを人間がレビュー。
- **Gate 2：Sheets API移行実装** — 架空データ→検証→グラフ/CSV/HTMLのCI・APIのモックテストを人間が確認。PRをマージするのは人間だけ。
- **Gate 3：実データ接続** — 人間がGoogle Cloud、シート共有、認証を設定してローカルで接続確認。秘密鍵や実データはPRにアップロードしない。
- **Gate 4：指標/AI分析** — 統計的先行性、為替補正、店舗間比較をレビューしてから追加。
- **Gate 5：対外公開/有料化** — 出典・商用利用・予測性能・料金を精査し、明示的承認後に公開。

## 自走の許容範囲と停止条件
- 同一ブランチ内のテスト作成・修正・リファクタリングは必要に応じ反復する。
- Googleシートへの書き込み、認証JSONの登録、課金有効化、mainへのマージ、公開デプロイは人間が行う/承認する。
- 各PRに成功・失敗した検証、未実施項目、最新の課金前提を記載する。

## 最初に再現するゴール
架空の3商品各5観測点を使い、商品001について`100,000円 → 88,000円 = -12.00%`をHTMLとCSVで再現。ネットワーク・Google認証は不要。

## 2026-11-14：Google Sheetsデータ源への移行ゲート

- Gate A: Google Sheets APIの料金・将来課金・認証方式を公式情報で調べ、設計書/ADRに残す。
- Gate B: Google APIのモック・架空データでPDCA（Plan→Do→Check→Act）、Ruff/pytest/CIで検証する。実データをCIに送らない。
- Gate C: 人間が移行PRをレビューしてmainにマージ。旧Excelの追跡解除と秘密管理方針を確認。
- Gate D: 人間がGoogle Cloud/サービスアカウント/シート共有を設定し、ローカルで実シート接続を確認。Google秘密鍵や実シートIDをPRへ貼らない。
- Gate E: 一定期間のデータ取得後、店舗ごとの価格種別・出典を追加する場合は別PRで承認。
