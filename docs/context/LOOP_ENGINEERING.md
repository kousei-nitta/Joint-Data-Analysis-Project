# 反復開発（Loop Engineering）と人間の承認ゲート

## 原則
AIは**個々の作業セッション内で**「計画→実装→自動テスト→原因分析→改善→再テスト」を必要な回数実施する。ただし、無人で将来にわたり走り続ける仕組みはこのリポジトリには存在しない。各モデルを変えても、事実・検証結果・次のタスクはGitHubのPRと本ディレクトリのドキュメントに残す。

## PDCAの単位
| 段階 | 担当AIの具体的動作 | 証拠 |
| --- | --- | --- |
| Plan | 入力仕様、対象ファイル、期待される出力、失敗時の扱いを確定 | PR本文・仕様書 |
| Do | 専用ブランチで最小単位の変更。原本Excelに書き込まない | コミットdiff |
| Check | `ruff check`、`ruff format --check`、`pytest`、デモHTML生成を実行 | 実行結果/CI |
| Act | 失敗原因を特定し、修正し、同じ検証を再実行。推測は未検証と区別 | 追記コミット/PR説明 |

## 承認ゲート（mainへの反映はユーザーが決める）
- **Gate 1：計画とスコープ** — 原本Excel不変、価格は日本円、既存シート仕様の解釈とMVP完了条件をPRでレビュー。
- **Gate 2：分析MVPの実装** — デモExcel→入力検証→集計→グラフ/CSV/HTMLの動作とテスト・CIの結果をユーザーが確認。通過後のみユーザーがPRをmainへマージ。
- **Gate 3：実データ受け入れ** — 入力担当者がExcelをpushした後、別ブランチで契約テストと実際の価格列・日付型を検証。列追加/データ修正は承認後。
- **Gate 4：指標やAI分析** — 統計的先行性、為替補正、店舗間比較等は分析定義と根拠を人間がレビューしてから実装。
- **Gate 5：対外公開・有料化** — データの取得・商用再利用の可否、検証結果、公開表現を確認後、明示的な承認を得て実施。

## 自走の許容範囲と停止条件
- 同一ブランチ内のテスト作成・修正・リファクタリング・PRコメント更新は自律的に繰り返す。
- 既存のExcel原本に手を加える、未承認の設計仕様を固定する、mainへpush/mergeする、外部公開・課金する段階では**停止して承認を求める**。
- 各PRでは成功したチェックだけでなく未実施のチェックと環境制約も記載する。未確認のUI実行を「動作確認済み」と書かない。
