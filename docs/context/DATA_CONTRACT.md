# Excel入力仕様・分析時のデータ契約（v0 / 暫定）

**根拠**：既存 `docs/plan.md` に書かれたExcel仕様。実際のワークブックと列型の照合は実装PRの最初に行い、差異があれば本書と処理を同時修正する。入力元 `product_prices.xlsx` は勝手に変更しない。

## 現在の2シート
| シート | 列 | 型・意味 | 必須 |
| --- | --- | --- | --- |
| 価格履歴 | 確認日 | Excel日付または解析可能な日付 | Yes |
| 価格履歴 | 商品ID | **文字列**、先頭ゼロ保持 | Yes |
| 価格履歴 | 価格 | 数値（通貨・税込区分は未確定） | Yes |
| 価格履歴 | 備考 | 任意の記録内容 | No |
| 商品マスタ | 商品ID | **文字列**、一意 | Yes |
| 商品マスタ | 商品名 | 表示名 | Yes |

- 空行は除去するが、途中に必須値が欠ける行は黙って除去しない。Excelの見出し1行を基準として**Excel上の行番号**をエラーに含める。
- 日付は形式を正規化する。曜日・時刻・タイムゾーンを暗黙に付与して分析に使わない。確認日のタイムゾーンは観測記録として日本時間を推奨（仕様追加時に確定）。
- 商品IDを数値へ変換しない（例：`001` と `1` は別ID）。商品マスタにない商品IDはエラー。
- 価格は数値で検証し、空欄を0とみなさない。負値はエラー。0円を許すかは未決定のため、当面は検査エラーとして要確認。
- マスタの重複ID、必要列不足、日付の不正、文字列としての不正価格を検査する。
- 同じ確認日・商品IDに複数行ある場合、勝手に平均・上書き・最新優先をしない。重複を報告し、仕様が決まるまで分析対象から保留する。

## 分析可能な単位と限界
現在のシートだけでは **店舗、商品状態、容量、通貨、税込/税抜、公開参考価格/実際の取引価格、出典URL、取得日時**を確実に区別できない。したがって、現行フォーマットの段階では、同じIDの単純な価格推移だけを試作し、店舗差や中国向け販路差を比較したことにはしない。

実データへの拡張前に必要な候補フィールド：
`shop_id`, `product_variant`, `condition`, `price_kind`, `currency`, `tax_basis`, `source_url`, `observed_at`, `china_trade_evidence`。これらは**未追加**であり、Excelを今すぐ変更する指示ではない。

## 例：ダミー計算仕様（別途fixtureを生成）
| 確認日 | 商品ID | 価格 |
| --- | --- | ---: |
| 2026-01-01 | 001 | 100000 |
| 2026-01-08 | 001 | 90000 |

期間変化率 = `(90000 / 100000 - 1) * 100 = -10.0%`。
データが1点のみ、過去価格が0、比較可能な過去日の記録がない場合は**値なし**として理由を表示する。未来予測は行わない。
